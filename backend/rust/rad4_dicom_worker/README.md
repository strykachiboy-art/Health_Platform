# RAD4 — bounded synthetic DICOM-rs validation worker

One-shot, **synthetic-only** validator built using DICOM-rs (`dicom-object = 0.10.0`).
The runner checks format and metadata before any clinical or archive action.

`rad4_dicom_worker inspect FILE SYNTHETIC_PATIENT_ID DICOM_ACCESSION STUDY_UID SERIES_UID SOP_UID FILE_SHA256 PIXEL_SHA256 [PREVIEW_OUTPUT]`

- Maximum file length: 4 MiB; accepts only regular non-symlink DICOM Part 10 files.
- Restricted to Explicit VR Little Endian and synthetic Secondary Capture / OT, unsigned 8-bit MONOCHROME2.
- Checks sorted unique DICOM elements and bounded lengths before independent DICOM-rs parsing.
- Compares patient ID, accession (DICOM SH 16-byte limit), Study/Series/SOP UIDs and supplied SHA-256 digests against trusted caller expectations.
- Output is compact JSON with status, digests and dimensions. No patient names, PHI or pixel bytes in stdout.
- Rejects non-synthetic patient IDs; optional non-diagnostic 8-bit PGM preview can only be written under `/output/rad4_preview_*.pgm` with exclusive creation. It is not windowed, interpreted or approved for clinical use.
- No database, network API, Orthanc writes, queue, retries, auto-association, signing, or chart release.
- Real-world transfer syntax, compressed images, and persistent worker scheduling are outside this phase. A verified clinical-authority pipeline is required first.

This is not a diagnostic DICOM decoder. Do not attach real patient files or use results to make clinical decisions.
The lockfile is generated by the pinned Rust builder and included in the exact-file commit **only after** all focused gates pass.
