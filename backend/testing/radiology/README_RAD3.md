# RAD3 — Synthetic Modality Worklist & DIMSE acquisition integration

**Strict test boundary.** This phase is a disposable laboratory validation. It is **not** live RIS→PACS synchronization, not radiologist certification, not actual scanner interoperability, not patient-level DICOMweb authorization, and not a clinical release.

The previous RAD1 foundation is the only source of truth for `RadiologyExam`, `RadiologyScheduledStep`, and ImagingOrder. The new `rad3_mwl_contract.py` is an **inert, synthetic-only** mapper and fail-closed candidate evaluator. It deliberately has no network client, database writer, route, migration, durable publication state, or clinical finalization action. In the live system, no clinician may publish MWL entries from patient data using this module until a separately designed authorized, durable outbox and identity/credential boundary are approved.

The executable harness uses **two** cached, version-tagged `orthancteam/orthanc:26.11.0` containers in a fresh, labeled Docker bridge network: `RAD3SRC` synthetic actor and `RAD3PACS` PACS receiving node. Each has its own labeled disposable volume. HTTP is bound only to `127.0.0.1`, with generated Basic credentials. The PACS DICOM port is available only inside that isolated network; it is **never** published on the host. The source's DICOM server is disabled. Resource cleanup checks exact test labels and volume ownership, and refuses unrelated resources. No application DB, existing Redis, existing Docker services, Flutter, clinical route, or historical migration is modified.

Critical accession interoperability: RAD1 internally generates `RAD-` plus 24 hexadecimal characters (28 total), whereas DICOM (0008,0050) is `SH` limited to 16 characters. The synthetic bridge derives a deterministic 16-character value *including issuer in its digest input*, but this is **not collision-proof** or approved for production. Before any real MWL publication, introduce a durable issuer-scoped unique DICOM accession allocation with database constraints, explicit Issuer of Accession Number semantics, and concurrency tests. Do not silently truncate internal accession numbers.

The gate proves synthetic RAD1-typed schedule→Orthanc Worklist POST/GET→actual cross-container DIMSE MWL C-FIND→reschedule→simulated modality native DICOM import→actual cross-container DIMSE C-STORE→Orthanc DICOMweb WADO→pixel and ID check→candidate study quarantine on wrong patient/stale order→PACS restart persistence→MWL cancellation disappearing from C-FIND. Credentials and real patient data are never written to evidence. Real scanner/clinical archive, reliable publication outbox, accession issuer reconciliation and regulatory/lawyer-reviewed plugin licensing remain future gates.

Do not re-run the installer once the target worktree exists, including after a failed gate. Send output for targeted existing-worktree recovery. The installer creates exactly five new files, runs 12 focused pure Python contract tests and the real disposable Orthanc gate, verifies cleanup/evidence/hash/source scope, then commits and non-force pushes only if every gate is green.
